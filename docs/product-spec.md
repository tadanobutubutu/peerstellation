# Peerstellation Web版 再構築仕様

## 1. 目的

訪問直後から操作可能な3D宇宙を表示し、ブラウザ内のHelia/libp2pノードが実際に観測したピアをリアルタイムで反映する。表示する値は実測値または明示された「不明」のみとし、疑似ピア、乱数レイテンシ、架空の所在地、架空のプロトコルは使わない。

## 2. 正確性の境界

- 可視化対象は「このブラウザノードから観測できた範囲」であり、IPFS全体の完全なトポロジーではない。
- `peer:discovery` は発見、`peer:connect` は接続成立、`peer:disconnect` は切断として別状態で扱う。
- 線はローカルHeliaノードと接続済みピアの間だけに描く。遠隔ピア同士の線は、実データがないため描かない。
- レイテンシはping成功時だけミリ秒表示し、失敗または未対応なら「未測定」とする。
- プロトコルはidentify後のpeer storeに存在する値だけを表示する。
- IPアドレスからの地理推定、ウォレット接続、Notion/ncli連携は製品目的に不要なため実装しない。

## 3. 初回体験

1. HTML解析時点でCSS製の深宇宙背景と中心光を表示する。
2. 小さい起動モジュールがThree.jsシーンを作り、ネットワーク初期化より先に最初のフレームを描く。
3. Heliaは最初の描画後に遅延ロードする。
4. 初期化中も3D空間は操作でき、状態ラベルは「観測装置を起動中」と表示する。
5. Heliaが失敗しても3D表示、説明、再試行ボタン、静的なアクセシブル代替表示は残す。

### 性能予算

- デスクトップのLCP: 1.8秒以下を目標、2.5秒を失敗閾値とする。
- モバイルのLCP: 2.5秒以下を目標、4.0秒を失敗閾値とする。
- 初期JavaScript: 350 KiB gzip以下。Heliaは初期チャンクへ含めない。
- 3D描画: 通常12 draw call以下、DPR上限1.5、追跡上限2,048、描画上限1,024。
- 60 Hz端末: デスクトップp75で55 FPS以上。省電力または小画面では30 FPS以上。
- 長いタスク: 起動後5秒間に50 ms超を3件以下。
- メモリ: 接続・切断を30分繰り返して、切断済みノードのThree.jsリソースが増え続けない。

## 4. ビジュアル設計

### コンセプト

名称は「Peerstellation」。一般的な青い管理画面、過剰なガラスカード、意味のない16進数、常時表示ログを避ける。3D宇宙そのものを主役にし、UIは観測機器の薄いレイヤーとして扱う。

### 画面構成

- 左上: 独自の軌道ロゴと製品名。右上は接続状態・実接続数・モーション・一覧入口だけ。
- 初期画面: 凡例、p50/p95、scope、説明文を描画しない。情報はピア選択または一覧ダイアログへ退避する。
- 中央: ローカルHeliaノードを恒星として表示。発見ピアは淡い紫の塵、接続済みピアは発光する天体、切断済みピアは死んだスレート色の星として履歴を残す。
- ノード詳細: カーソルを重ねた時、キーボードで選択した時、またはタップした時だけ、対象ノードの画面座標へアンカーする。
- モバイル: 上部を1行に圧縮し、タップしたノードの横へカードを配置する。下部固定シートは使わない。
- 操作: `WASD` と矢印キーはカメラ移動・旋回・俯仰、左ドラッグは押下中だけの軌道操作、右クリックはカメラモードの固定切替、`Escape` はホバーモード復帰と選択解除に使う。標準的なゲームパッドでは左スティックが移動、右スティックが旋回・俯仰、肩ボタンまたはトリガーが速度ブーストになる。ホバーモードではポインターをノードへ重ねた瞬間に対象ノードから情報カードを伸ばす。これらの手順は設定ダイアログの `Controls` カテゴリーにも掲載する。
- 空間スケール: pingを対数二乗曲線で距離へ写像し、距離の揺らぎはpeer IDから決定的に生成する。製品上の距離に人工的な上限は設けず、有限値だけを受け入れる数値ガードとレンダー遠平面1,000,000を安全境界にする。自動カメラの上限360（縦長220）とは独立しているため、高遅延・未測定ピアは画面外へ残り、探索操作では自動構図を超えて手動移動できる。
- 自動フレーミングはブラウザliveまたはping実測済みを優先し、未計測Kuboの全件を半径計算へ入れない。liveがまだ無いKubo-onlyの開始時は、世界座標が近い決定的な24件だけを導入点として選び、残りのノードの距離と分布は変更しない。
- プレイヤーが旋回・移動・ズームを開始すると自動フレーミングを解除し、後続のピア更新で自動ズームを再開しない。`Home`、`0`、または `R` の明示的なカメラリセットだけが自動フレーミングを再有効化する。タッチ端末の二本指ピンチはホイールと同じ距離計算へ入り、ピンチアウトでズームイン、ピンチインでズームアウトする。
- 設定: 初期値は自動品質。最低・低・中・高・最高の手動プリセットと、ピクセル比、アンチエイリアス、星雲／星屑密度、ノード詳細度、線の明るさ、空間パノラマ、露出、フォグ、モーション、カメラ感度、データ層、レイテンシ表示を端末内設定ダイアログで変更できる。Controlsでは移動・旋回・俯仰・ズーム・速度ブーストを任意のKeyboardEvent.codeへ再割り当てできる。Language and regionでは自動に加えてISO 639-1の184タグと`zh-CN`を選べる。185タグすべてに197キーの静的パックを用意し、選択時だけ遅延読み込みする。7タグは編集済み、低リソース言語は橋渡し言語を明示した暫定パックとして検証対象を追跡する。言語カバレッジ一覧には生成パックの実測翻訳率と橋渡し先を表示する。クレジットの法的識別子は原表記を保ち、説明文を選択言語へ切り替える。端末の言語・タイムゾーンだけを使う地域ヒントを選べ、IPアドレス、multiaddr、正確な位置情報は地域判定に使わない。設定はlocalStorageのバージョン付きスキーマで検証し、壊れた値は安全な既定値へ戻す。

### 色と文字

- 背景: `#03050a`、深部: `#080b18`。
- 本文: `#f4f7ff`、補助文: `#bac5da`。
- 実接続: `#68f0d0`、発見: `#84a7ff`、Kubo観測: `#f6c76a`、切断履歴: `#697386`、警告: `#ffd089`、失敗: `#ff7f92`。
- 通常本文のコントラスト比は7:1以上、操作境界は3:1以上。
- 外部フォントを読込まず、`ui-sans-serif` と `ui-monospace` を使う。

### 動き

- ノード出現は600 ms以内、接続パルスは900 ms以内。
- 常時点滅、スキャンライン、グリッチ、パネル傾斜は使わない。
- `prefers-reduced-motion: reduce` では自動回転、カメラ慣性、パルス、残光を停止する。
- UIの「動きを止める」はOS設定に関係なく全アニメーションを停止できる。

## 5. アクセシビリティ

- WCAG 2.2 AAを必須、色コントラストと本文可読性はAAAを目標とする。
- `<main>`、見出し順、skip link、`<section>`、`<button>`、`<dialog>`相当の意味構造を持つ。
- canvasには短い代替名と詳細説明への参照を付ける。
- ピア一覧をDOMで提供し、各ピアをキーボードで選択できる。
- 接続数の変化は集約して通知し、ピアごとの高頻度イベントをlive regionへ連投しない。
- 200%文字拡大で情報を失わず、320 CSS px幅で横スクロールを発生させない。
- 44×44 CSS px以上の操作領域、見えるフォーカス、Escで閉じる操作を保証する。
- WebGL/WebGPUが使えない場合も、ノード状態とピア一覧を利用できる。
- axeの重大・深刻違反を0件、キーボードのみの主要導線完走を必須とする。

## 6. ネットワーク構成

- ブラウザ用の軽量libp2p構成を使い、WebTransport/WebRTC/WebRTC Direct/WebSocket/リレー、Noise、Yamux/Mplex、identify、ping、bootstrap、client-mode Amino Kad-DHT bounded queryを有効にする。WebTransport非対応ブラウザではmultiaddrの適合判定により他の対応transportへフォールバックする。
- bootstrapリストは依存する`@helia/libp2p`の公開リストを同じバージョンで固定し、アプリの表示データや疑似ピアとは混ぜない。依存更新時にリストも再確認する。
- WebRTCを利用できるよう、Helia/libp2pはWindow側で遅延初期化する。
- イベントを型付きの`PeerObservation`へ正規化し、描画へは最大10 Hzでバッチ反映する。
- `getConnections()`で初期スナップショットを取り、イベント登録前後の取りこぼしを補う。
- pingは接続済みピアに限定し、同時実行2件、5秒タイムアウト、各ピア30秒以上の間隔を設ける。
- Kuboの接続表はブラウザHeliaと別ソースである。Peer explorerの明示操作時だけ、CORSを許可した`127.0.0.1:5001`へ`/id`と詳細付き`/swarm/peers`をPOSTし、`source: "kubo"`として表示する。成功後は15秒周期で同じ明示オプトインを更新し、ページ離脱またはエラーで停止する。`/p2p-circuit`のリレーIDが両端の観測集合に存在する場合だけ、Kubo同士のリレー線を描く。ロード時の自動アクセス、`*`許可、認証情報の転送はしない。
- ブラウザが観測できるのはローカルノードの直接接続だけであり、リモートピア同士の接続は共有された証拠がない限り線を引かない。接続成立後の証拠線は切断イベントまで安定して残し、切断済みの星は履歴として死んだ色で残す。Kuboの外周ノードは別プロセスの観測であり、ブラウザの中心線には含めない。
- IndexedDBには公開peer ID、状態、最終観測時刻、実測レイテンシだけを保存する。秘密鍵と完全なmultiaddrは保存しない。
- 地域ヒントは端末の言語とIANAタイムゾーンから国レベルより粗い候補を作るだけで、確度は常に `approximate` とする。静的アセット配信はCloudflareの `request.cf` を受け取れないため、IP・GeoIP API・GPSは使わない。将来Worker化してエッジ国コードを導入する場合も、オプトイン・非保存・無効化可能を満たすまで実装しない。

## 7. WASMの責務

### Rust

- 1,024ノードまでの位置を保持し、品質に応じた近傍予算（デスクトップ最大256、モバイル最大96）の速度、中心引力、反発、減衰を毎フレーム更新する。予算外のKubo観測と高遅延ピアは実測半径のまま静的に保持し、ブラウザliveの中心領域と潰さない。製品上の距離に人工的な上限は設けず、有限値ガードとレンダー遠平面1,000,000だけを数値境界とする。自動カメラ上限360（縦長220）とは別物であり、手動カメラにUI上限を設けず、ノードの意味上の距離を縮めない。
- 中心線と、両端の観測記録があるリレー線の位置・輝度を計算する。
- ピアイベントのバッチから接続数、発見数、レイテンシp50/p95、ジッター、健全性スコアを算出する。
- 固定容量のWASM ABIを使い、Rust `wgpu` は背景・線・ノードのGPUバッファを直接更新する。`wasm-bindgen`のJavaScript生成物は追跡しない。
- TypeScriptへ毎フレームの位置・線分配列を戻さない。`step(deltaSeconds, activeCount, motionScale)`、`layout_edges(count)`、`analyze(count)` は境界値0、最大件数、未測定レイテンシを安全に処理する。

### TypeScript

- DOM、Heliaイベント正規化、状態管理、レンダラー連携、WASMロード、配信処理を担当する。
- TypeScript 7系を使い、整形・通常Lint・import整理はBiomeへ統一する。ESLintはセキュリティ監査とJSXアクセシビリティ監査の専用構成として併用する。
- リポジトリが所有する`.js`と`.jsx`は0件にする。依存物とビルド出力は追跡しない。

### Rust wgpuとThree.jsフォールバックの境界

- Rust `wasm32-unknown-unknown` の `wgpu` レンダラーはノード位置・速度・反発・中心/リレー線分の位置と輝度、ピア集計と遅延統計に加え、背景・線・ノードの3描画パスを担当する。TypeScriptは観測・入力・設定・DOMの意味構造を担当し、固定容量の描画バッファだけをRustへ渡す。
- Rust `wgpu` はWebGPUを優先し、同じRust ABIでWebGL2へフォールバックする。WASM取得・初期化・GPUアダプターのいずれかが失敗した場合、または `?renderer=three` を明示した場合だけ、完全なThree.js WebGPU → WebGL2経路へ切り替える。両経路は同じノード状態・遅延距離・切断履歴・リレー線・選択カード・設定・診断属性契約を満たす。背景パノラマ、FogExp2、露出、品質予算、パルス式、10層ホストの順序と半径、密集時コロナ拡大率（最大1.22倍）、モバイル星屑上限480点は共有仕様で固定する。描画プリミティブはThreeのIcosahedron/TorusとRustの解析的ビルボードで異なり、ピクセル完全一致ではなく意味・投影・階層の一致を受入条件とする。Rustの固定3パスを維持するためKubo/切断マーカーのブレンド式とGPUタイムスタンプはバックエンド固有値として報告する。モバイルもRust WebGL2を優先し、Three.jsは最後の互換経路として保持する。
- `three-ui` 1.1.1はReact 16向けの古い2Dコンポーネント集でThree.js UIではない。`@darrylondil/react-three-ui` 0.2.0はReact Three Fiber専用の別ライブラリであり、現行のDOMアクセシビリティと初期性能を壊さないため、全画面置換には使わない。CSSはTailwind CSS 4.3のViteプラグインで設計トークンを管理し、React/Babel/PostCSSを前提とするStyleXは採用しない。

## 8. 安全性

- `innerHTML`へネットワーク由来文字列を渡さず、`textContent`を使う。
- CSPはインラインscript、`unsafe-eval`、外部フォントを許可しない。
- GitHub Actionsの権限はジョブ単位で最小化する。
- 第三者Actionは完全なコミットSHAへ固定するか、単純なコマンドへ置換する。
- PRコードをwrite tokenまたはOIDC付きAIエージェントへ渡さない。
- `npm audit --omit=dev` のhigh/criticalを0件、開発依存も例外理由なしのcriticalを0件とする。
- peer ID、エラー、URLをログへ出す際は長さを制限する。

## 9. Web専用化

- `local/`、Notion書き出し、ncli記述、`isLocal`による実装切替を削除する。
- 開発サーバーと本番は同じ実Heliaコードを使う。違いは診断ログとソースマップだけとする。
- IPFS Desktopは外部の開発・検証ノードであり、削除や同梱をしない。

## 10. 配信

- Cloudflare Workers Static Assetsを主配信にし、静的アセット要求を無料枠内で配る。
- Pinataは配信元ではなく、各リリース成果物のIPFSピンとDNSLink用CIDの生成に使う。
- HTMLを拒否するPinata public gatewayへ本番トラフィックを依存させない。
- デプロイ順は、検査、ビルド、Cloudflare静的配信、Pinataピン、DNSLink更新とする。
- 失敗時は直前のCloudflare版とIPFS CIDを保持する。

## 11. 品質評価

- LLMを実行しない製品のため、Instructor、Outlines、Guidance、Guardrails AI、NeMo Guardrails、Llama Guard、Prompt Guard、Ragas、Langfuse、Phoenixをランタイム依存へ追加しない。
- Promptfoo、DeepEvalも製品挙動を検査できないためCI依存へ追加しない。
- AI生成物の品質は、固定されたデザイン採点表、Claude Codeの独立査定、ブラウザ実測、axe、Lighthouse、Playwright、型検査、単体テストで評価する。
- 無関係なAI安全製品を大量導入して依存面と保守面を増やすことを、品質向上とは見なさない。

## 12. 合格条件

- 公開URLで1秒以内に宇宙背景、2.5秒以内に操作可能な3Dを確認できる。
- 公開環境で疑似ピア生成コードが実行されない。
- 実ピア接続を最低1件、peer IDと接続状態をDOM一覧と3Dの両方で確認できる。
- Rustの物理・解析WASMが正しいWebAssembly moduleとしてビルドされ、ブラウザでロードされる。
- 手書き`.js/.jsx`、追跡`node_modules`、追跡`dist`が0件。
- 型検査、単体、WASM、E2E、axe、ビルド、依存監査の必須ゲートが成功する。
- Claude Codeの辛口再審査で、致命傷0件かつ80/100以上を得る。未達なら指摘を再実装する。
